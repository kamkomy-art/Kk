# tehlil — CLAUDE.md

تطبيق تحليل فني للعملات الرقمية بالذكاء الاصطناعي: يجيب بيانات سوق حيّة، يحسب مؤشرات فنية
حقيقية بكود رياضي، ثم يطلب من Claude تفسيرها نصيًا. **القرار النهائي بالشراء/البيع يعود
للمستخدم دائمًا** — لا توصيات مباشرة، لا تنفيذ تلقائي لأي صفقة.

## الهيكل

- `lib/binance.js`: يجلب الشموع (`/api/v3/klines`)، السعر خلال 24 ساعة (`/api/v3/ticker/24hr`)،
  وقائمة الرموز (`/api/v3/exchangeInfo`, مخزّنة مؤقتًا لساعة) من Binance العامة — **بدون مفتاح
  API**. أي خطأ شبكة أو رمز غير صحيح يُرمى كـ `Error` عادي ليلتقطه `server.js`.
- `lib/indicators.js`: حسابات رياضية بحتة (SMA، EMA، RSI بتنعيم Wilder، MACD، Bollinger
  Bands) — لا اعتماديات خارجية. `analyzeCandles(candles)` هي نقطة الدخول الرئيسية: تُرجع أحدث
  قراءة لكل مؤشر + تصنيف نصي عربي (مثل "تشبع شرائي"، "اتجاه صاعد"). القيم `null` عندما لا تتوفر
  بيانات كافية (مثل عملة حديثة الإدراج لا تملك 200 شمعة لـ SMA200).
- `server.js`: أربع نقاط API:
  - `GET /api/watchlist` — يحسب المؤشرات لقائمة عملات ثابتة (`WATCHLIST`)، مع تخزين مؤقت 20 ثانية
    لتفادي إغراق Binance بالطلبات عند التحديث المتكرر من الواجهة.
  - `GET /api/search?q=` — بحث عن رموز USDT مطابقة.
  - `POST /api/analyze` — يجلب بيانات عملة محددة، يحسب المؤشرات، ثم يستدعي Anthropic (غير
    متدفق، رد واحد كامل) مع system prompt يمنع Claude من إصدار توصية شراء/بيع مباشرة ويُلزمه
    بإخلاء مسؤولية في نهاية كل رد.
  - `POST /api/messages` — proxy عام (موروث من النسخة الأولى) لدردشة حرة متدفقة (SSE) عبر
    `Readable.fromWeb`.
- `src/api/client.js`: طبقة fetch رفيعة لكل نقاط `/api/*` — يرمي `Error` مع رسالة عربية عند
  الفشل؛ `analyzeSymbol` يُرفق `error.partial` بالبيانات الجزئية (المؤشرات) حتى لو فشل استدعاء
  Claude تحديدًا، حتى تبقى الواجهة قادرة على عرض الأرقام رغم فشل التفسير النصي.
- `src/components/`: `Watchlist` (يحدّث كل 30 ثانية)، `SearchBar` (debounce 300ms)،
  `AnalysisPanel` (يستدعي `/api/analyze` عند تغيّر `symbol`)، `Chat` (streaming حر، منفصل عن
  سياق العملة المختارة عمدًا لإبقائه بسيطًا).

## قرارات تصميم متعمّدة

- **لا يوجد tool-use loop بين Claude والبيانات.** الخادم يعرف مسبقًا أي عملة يُحلّل (يأتي `symbol`
  في جسم الطلب)، فيجلب البيانات ويحسب المؤشرات *قبل* استدعاء Claude، ويُرسلها كسياق نصي جاهز.
  إعطاء Claude أداة يقرر بنفسه متى يستدعيها كان سيضيف تعقيدًا بلا فائدة هنا — القرار (أي عملة)
  محسوم مسبقًا من واجهة المستخدم، وليس شيئًا يحتاج Claude لاستنتاجه.
- **حسابات المؤشرات كلها كود عادي، لا يمر أي رقم عبر Claude قبل حسابه.** هذا مقصود لأنه تطبيق
  مالي — الدقة الرقمية أهم من المرونة، ولا مجال لتخمين النموذج لقيمة RSI أو MACD.
- **`ANTHROPIC_API_KEY` يُقرأ فقط من طرف الخادم** (عبر `dotenv`)، لا يصل أبدًا لكود العميل.

## أوامر مفيدة

- `npm run dev` — يشغّل `server.js` و`vite` معًا.
- `npm run build` — يبني حزمة الإنتاج لواجهة React فقط.

## ملاحظات شبكة

`lib/binance.js` يستدعي `api.binance.com` مباشرة (بدون proxy أو مفتاح). في بيئات ذات قيود
شبكة (egress allowlist)، تأكد من السماح بهذا المضيف صراحةً، وإلا سترجع نقاط `/api/watchlist`
و`/api/search` و`/api/analyze` خطأ 502 برسالة عربية واضحة (سلوك متوقع، وليس عطلًا في الكود).
